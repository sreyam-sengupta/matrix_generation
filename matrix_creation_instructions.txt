These are the instructions to create a matrix. These instructions assume you have the 7*12 (BE price
* GHG price) MAgPIE scenario outputs already created — both price-driven and demand-driven runs.
For example, if your output folder is called output_folder, you should have a directory structure as
follows:

<repo_name>/magpie/output/<output_folder_name>/SSP2_BD-{BD_val}/
  [where BD_val is "none" or "high", referring to the biodiversity scenario]

In this directory you should have folders named:

  SSP2_BD-{BD_val}_BE{BE_val}_G{GHG_val}price_rev{N}   (price-driven runs, 7 per BD scenario)
  SSP2_BD-{BD_val}_BE{BE_val}_G{GHG_val}demand_rev{N}  (demand-driven runs, 84 per BD scenario)

where BE_val is "00", "05", "07", "10", "15", "25", "45"; GHG_val is "0000", "0010", ..., "4000";
and rev{N} is the revision number (e.g. "rev2", "rev3").

For example:
  output/Spatially_resolved_BII_rev2/SSP2_BD-none/SSP2_BD-none_BE00_G0000demand_rev2

Assuming you have all these, the next step is to create a matrix. For this, please use the files
on the add_woodfuel_to_bioenergy branch of the matrix generation repo:
https://github.com/sreyam-sengupta/matrix_generation/tree/add_woodfuel_to_bioenergy

Below, we briefly describe each file and what it does.

***************************************************************************

(I) "2026-03-20_MMEmu_createMatrix-MP_loop_trimmed.R"

This is the main matrix generation script. It processes MAgPIE outputs into a matrix ready for
MESSAGE. There are 3 stages: "raw", "map", and "matrix". These are described briefly below:

(a) "raw" phase: the first and most time-consuming phase. The script checks if each run is finished,
then extracts variables from both 'fulldata.gdx' and 'report.mif' (including bioenergy prices from
the price-driven runs), and writes them to a "raw" file. Output: 84 files named
"SSP2_BD-{BD_val}_BE{BE_val}_G{GHG_val}raw.csv", stored in the matrix output folder. Variables
still have their MAgPIE names at this stage.

(b) "map" phase: translates the raw files from MAgPIE to MESSAGEix naming conventions (variable
renaming, aggregation, and unit conversions). Uses the mapping file. Each of the 84 raw files
becomes a "map" file; at the end all 84 are aggregated into a single premap file named
"magpie_input-premap_SSP2_BD-{BD_val}_trimmed_{timestamp}.csv".

(c) "matrix" phase: the shortest phase. Takes the premap file and renames regions to MESSAGEix
names, reorders and reformats the data into the final matrix ready for MESSAGEix input. Output:
"2026-03-20_magpie_input_SSP2_BD-{BD_val}.csv".

User input section (lines 12-86 of the script):
  Line 18:  bd_scenario — "none" or "high" (can also be passed as a command-line argument)
  Line 22:  base_output_dir — the MAgPIE output folder containing the runs
  Line 28:  scenario_name — prefix for run folder names (e.g. "SSP2_BD-none")
  Line 31:  run_suffix_demand — suffix for demand-driven run folders (e.g. "demand_rev2")
  Line 32:  run_suffix_price  — suffix for price-driven run folders (e.g. "G0000price_rev2")
  Line 35:  be_price_values_all — list of BE price levels to process (default: 0,5,7,10,15,25,45)
  Line 53:  ghg_price_values — list of GHG price levels to process (default: 0,10,...,4000)
  Line 56:  matrix_output_dir — folder where output matrix files are written
  Line 62:  map_file — path to the mapping CSV (file II below)
  Line 65:  vars_to_keep_file — path to the variable filter CSV (file III below)
  Line 71:  phases — which phases to run ("raw", "map", "matrix"); can be overridden at runtime by
            setting the environment variable PHASES_FILTER (e.g. PHASES_FILTER="map,matrix" to skip
            the raw phase when raw files already exist)
  Lines 80-85: other settings (reduced_messages, loop, check_file, correct_emissions, baseyear)
            — these usually do not need to be changed.

The script is designed to be run in parallel using the master bash script (file IV below):
  Rscript 2026-03-20_MMEmu_createMatrix-MP_loop_trimmed.R none  # BD-none scenario
  Rscript 2026-03-20_MMEmu_createMatrix-MP_loop_trimmed.R high  # BD-high scenario

***************************************************************************

(II) "2026-03-20_map_magpie_message_human_corrected.csv"

The mapping file. It contains instructions on how to translate MAgPIE outputs into MESSAGEix-
readable input: variable renaming, aggregation, and unit conversions. Columns:
  - piam_variable: MAgPIE variable name (PIAM = PIK Integrated Assessment Model)
  - Variable: MESSAGEix variable name
  - factor: unit conversion factor (e.g. Mt N2O/yr -> kt N2O/yr uses factor 1000)
  - weight: aggregation weight when many MAgPIE variables map to one MESSAGEix variable
            (NULL = uniform weights)
  - spatial: spatial aggregation level ("reg+glo" = both regional and global)

This file is a data file and an instruction to the matrix script. It is usually not modified.

***************************************************************************

(III) "2026-03-20_vars_to_keep.csv"

A list of MESSAGEix variable names that will be retained in the final matrix. All other variables
are dropped after the map phase. This file is also an instruction to the matrix script and is
usually not modified.

***************************************************************************

(IV) "2026-03-20_run_matrix_pipeline.sh"

The master bash script that orchestrates the full matrix generation pipeline. It launches the
main loop script (file I) in parallel for each BD scenario and BE price level, then runs the
post-processing scripts (files V and VI) on the completed matrices. Usage:

  bash 2026-03-20_run_matrix_pipeline.sh              # sequential
  PARALLEL=true bash 2026-03-20_run_matrix_pipeline.sh  # parallel (recommended)

To skip the raw phase (if raw files already exist):
  PHASES_FILTER="map,matrix" bash 2026-03-20_run_matrix_pipeline.sh

***************************************************************************

(V) "2026-03-20_add_bioenergy_prices.R"

Post-processing script that adds three bioenergy price columns to the final matrix output from
file I. It reads both the price-driven GDX files and both price- and demand-driven report.mif
files to construct three distinct bioenergy price variables:

  P1 — Price|Primary Energy|Biomass_exo_P1
       The exogenous bioenergy subsidy, read directly from the GAMS parameter
       i60_2ndgen_bioenergy_subsidy in the price-driven fulldata.gdx. This is the subsidy that
       was imposed on the model to incentivise bioenergy production. For BE00 runs it is always
       zero; for BE45 it follows a linear 0->45 US$/GJ trajectory over time.

  P2 — Price|Primary Energy|Biomass_endo_P2_price-driven
       The endogenous market-clearing price of bioenergy, read from Prices|Bioenergy in the
       price-driven report.mif. This is the shadow price (marginal) of the supply-demand balance
       equation oq16_supply_crops for bioenergy crops (begr/betr). It reflects the equilibrium
       price resulting from the imposed subsidy.

  P3 — Price|Primary Energy|Biomass_endo_P3_demand-driven
       The same endogenous market-clearing price, but read from the demand-driven report.mif.
       This reflects the bioenergy price when bioenergy demand is fixed exogenously (derived
       from the price-driven runs) rather than driven by a price incentive.

These three columns capture different aspects of bioenergy pricing and are all appended to the
final matrix. The script is called automatically by the master pipeline script (file IV) after
the matrix phase completes.

***************************************************************************

(VI) "2026-04-09_add_woodfuel_to_bioenergy.R"

Post-processing script that updates an already generated matrix by adding woodfuel energy into
"Primary Energy|Biomass". It is designed to run after file V.

What it does:
  1. Reads the matrix with BE prices, e.g.
     "2026-03-20_magpie_input_SSP2_BD-none_with_BE_prices.csv"
  2. Loops over all 84 demand-driven runs (7 BE x 12 GHG) and reads each run's fulldata.gdx.
  3. Extracts woodfuel demand from:
       pm_demand_forestry[woodfuel]  (mass units)
  4. Reads mass-to-energy coefficient from:
       fm_attributes[woodfuel, ge]   (GJ/tDM)
  5. Converts mass to energy and maps region names to matrix regions:
       EJ = (million tons) * 1e6 * (GJ/t) / 1e9
  6. Adds the resulting EJ values to existing rows:
       Variable == "Primary Energy|Biomass"
  7. Writes a new output matrix:
       "2026-04-09_magpie_input_SSP2_BD-{BD_val}_with_woodfuel.csv"

No raw/map/matrix rerun is needed for this step. This script can be used both in the full
pipeline and for backfilling previously generated matrices.

***************************************************************************

(VII) "2026-04-09_woodfuel_verification.R"

Verification script located at:
  /p/projects/magpie/users/sreyamse/running_output/scripts/2026-04-09_woodfuel_verification.R

It compares the matrix before and after woodfuel addition and reports:
  - whether all expected World biomass scenario rows are present (84 = 7 BE x 12 GHG)
  - yearly global deltas after woodfuel addition
  - sample scenario-level deltas (e.g. 2050 and 2100)

Use this script after running file VI to verify that woodfuel was integrated correctly.
