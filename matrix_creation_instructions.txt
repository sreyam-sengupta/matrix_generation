These are the instructions to create a matrix. These instructions assume you have the 7*12 (BE price * GHG price) MAgPIE scenario outputs already created. For example, if your output folder is called output_folder, and you did not make any changes in the output file names, then you should have a directory structure as follows:

<repo_name>/magpie/output/<output_folder_name>/SSP2_BD{BD_val}/ [where BD_val is two digits representing the BII target, e.g. "00" or "78"]

And in this above directory you should have files named:

SSP2_BD{BD_val}_BE{BE_val}_G{GHG_val}demand_rev{rev_val} [where BE_val is "00", "05",..., "45"; GHG_val is "0000", "0010",..., "4000"; and rev_val is "1", "2" etc.].

For example, in my output folder, the directory is called: "/p/projects/magpie/users/sreyamse/magpie/projects/PIK_2025-07-02/magpie/output/Matrix_test_rev1/SSP2_BD00" and a sample output scenario from this directory is called "SSP2_BD00_BE00_G0000demand_rev1".

Assuming you have all these, the next step is to create a matrix. For this, please download the necessary matrix creation files from the matrix repo we have created: https://github.com/sreyam-sengupta/matrix_generation

Below, we briefly discuss what the files here are used for.

***************************************************************************

(I) "2025-11-18_MMEmu_createMatrix-MP_loop_trimmed.R" - this is the matrix generation script, the longest and most important file. It contains all the instructions to process the MAgPIE outputs into a matrix that is ready for MESSAGE. There are 3 stages here: "raw", "map", and "matrix". I briefly describe what those steps mean:

(a) "raw" phase: this is the first and most time-consuming phase. In this phase, the script first checks if each run is finished, then extracts variables (both from the 'fulldata.gdx' as well as 'report.mif') including prices (the price-driven runs are needed here), and writes them to a so-called "raw" file. The output of this step are 84 files named "SSP2_BD{BD_val}_BE{BE_val}_G{GHG_val}raw.csv" and they are stored in a folder of your choice. In this files, the variables still have their MAgPIE names.

(b) "map" phase: in this phase, the raw files are "translated" from MAgPIE to MESSAGEix. Basically, the variables are either renamed or aggregated from their MAgPIE names to MESSAGEix naming conventions. All unit conversions are also done in this step. The mapping file is required in this step. During this step, each of the 84 raw files is converted into a "map" file with the name "SSP2_BD{BD_val}_BE{BE_val}_G{GHG_val}map.csv", and at the end of the map phase, these 84 map files are all aggregated to a single premap file called "magpie_input-premap_SSP2_BD00_trimmed_{timestamp}.csv".

(c) "matrix" phase: this is the shortest phase, it takes the premap file generated in the map phase and renames the regions to MESSAGEix names, and reorders, reformats, and otherwise organizes the premap file into a clean matrix ready for MESSAGEix. The output of this step is the final matrix that you can use for MESSAGEix input.

User input section of matrix creation file: there are several places where your user input is required:
Line 14: the output folder of your MAgPIE main folder where the runs are being generated.
Line 17: scenario name prefix ("SSP2_BD00" in our case).
Line 20 & 21: run suffixes for price-driven and demand-driven runs (if you didn't change the default in the MAgPIE "GENIE_Di_script.R", then no need to change these).
Line 24: the BE_price values that the script expects (change these if you want to run a reduced matrix, e.g. only with BE00 and BE45).
Line 42: the GHG_price values (same principle, change these if you are running a reduced matrix, e.g. GHG0000 and GHG4000).
Line 45: the folder where you want to keep the output matrix.
Line 48: the location of the map file.
Line 51: the location of the "vars_to_keep" file.
Line 57: the phases (raw, map, and matrix); only change these if you are re-running the matrix generation script, and already have the raw files, for example.
Lines 61-66: other settings that you usually will not need to change.

***************************************************************************

(II) "2025-11-28_map_magpie_message_human_corrected.csv" - this is the map file. It contains instructions on how to translate the MAgPIE outputs into MESSAGEix-readable input. For example, if a variable name needs to be translated, or several variables need to be aggregated, or if units need to be converted. The first column "piam_variable" is the MAgPIE name (PIAM stands for "PIK Integrated Assessment Model"); the second column "Variable" is the name MESSAGEix expects; the third column "factor" is the unit conversion factor (e.g., MAgPIE reports N2O emissions in Mt N2O/yr but MESSAGEix expects them in kt N2O/yr); the fourth column "weight" is if many MAgPIE variables need to be aggregated to a single MESSAGEix variable, with non-uniform weights ("NULL" means uniform weights I think); and finally "spatial" column is the spatial aggregation level ("reg+glo" means both regional and global aggregations will be created).

This file is a data file, and an instruction to the matrix generation script. It is usually not meant to be modified.
